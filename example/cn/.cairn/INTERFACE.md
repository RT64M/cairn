# API 约定

## 基本原则

- API 使用版本化路径；
- 所有业务错误返回统一错误结构；
- 列表接口统一支持分页、排序和筛选摘要；
- 写操作需要幂等键或后端幂等保护；
- 后端返回权限能力，前端根据能力展示操作入口。

## 认证

| 项 | 约定 |
| --- | --- |
| 登录来源 | 企业 SSO |
| 会话类型 | 安全 Cookie |
| 权限来源 | 后端根据 SSO 组映射角色和团队 |
| 前端职责 | 展示登录状态和能力入口，不做最终授权 |

## 资源

| 资源 | 说明 |
| --- | --- |
| Tickets | 工单列表、详情、状态流转 |
| Assignments | 工单负责人和历史分派 |
| Notes | 客服备注和可见性 |
| Audit Events | 敏感操作记录 |
| Notifications | 通知任务状态 |
| Exports | 导出任务和文件状态 |

## 关键接口

| 接口 | 说明 | 主要错误 |
| --- | --- | --- |
| 查询工单列表 | 根据队列、状态、团队、SLA 风险筛选工单 | 无权限、筛选条件非法 |
| 获取工单详情 | 返回工单、备注、分派历史和可用操作 | 工单不存在、无权限 |
| 批量分派 | 将一组工单分派给团队或负责人 | 部分失败、幂等冲突、负责人不属于团队 |
| 创建备注 | 为工单追加备注并写入审计 | 字段非法、敏感词策略失败、无权限 |
| 查询审计事件 | 按工单、操作者、事件类型和时间范围查询 | 无权限、范围过大 |
| 创建导出任务 | 根据筛选条件生成导出文件 | 无权限、导出范围过大 |

## 错误结构

| 字段 | 说明 |
| --- | --- |
| code | 稳定错误码，供前端映射文案 |
| message_key | 用户可见文案 key |
| request_id | 排查问题使用 |
| field_errors | 字段级错误列表 |
| retryable | 是否可以由用户修改输入后重试 |
| details | 面向调试的有限上下文，不包含敏感数据 |

## 批量分派结果

批量分派接口需要区分整体结果和逐项结果：

| 结果 | 说明 |
| --- | --- |
| success_count | 成功分派数量 |
| failed_count | 失败数量 |
| retryable_items | 修改负责人、团队或筛选条件后可重试的条目 |
| blocked_items | 当前用户无权操作或工单状态不允许操作的条目 |
| operation_id | 本次批量操作的追踪 ID |

## API 文档维护规则

- 新增接口时同步 `TEST.md` 的契约测试范围；
- 新增错误码时同步本文件的错误结构说明；
- 修改权限语义时同步 `ARCHITECTURE.md` 的权限边界；
- 发现接口与实现不一致时进入语义命名的 `fix_<desc>.md`，再落到 `TODO.md`。
