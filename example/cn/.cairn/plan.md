# Northstar Ops plan

## 项目定位

Northstar Ops 是一个面向内部运营团队的工单协作平台。它帮助客服、履约、财务和运营主管在同一个界面中查看客户请求、分派负责人、记录处理备注、跟踪 SLA，并保留审计轨迹。

本项目采用前后端分离：

- Web 前端负责工作台、列表筛选、详情页、批量操作和多语言展示；
- API 后端负责认证、权限、工单状态机、审计日志、通知和报表聚合；
- 后台任务负责 SLA 预警、通知重试、日报生成和过期数据清理。

## 当前版本目标

当前阶段目标是交付运营团队可用于试点的 MVP：

- 支持 SSO 登录和团队权限；
- 支持工单列表、工单详情、分派、备注和状态流转；
- 支持批量分派与批量关闭；
- 支持客服备注审计；
- 支持基础 SLA 预警；
- 支持中文和英文界面文案；
- 支持审计日志导出。

## 非目标

- 不做公开注册；
- 不做客户自助门户；
- 不做移动端原生应用；
- 不做复杂 BI 报表；
- 不接入实时聊天；
- 不支持跨租户共享工单。

## 核心用户

| 用户 | 主要需求 |
| --- | --- |
| 客服专员 | 快速认领、备注、转交和关闭工单 |
| 运营主管 | 批量分派、查看 SLA 风险、抽查处理质量 |
| 财务协作人 | 查看与退款、补偿相关的工单并补充处理状态 |
| 系统管理员 | 管理团队、权限、审计导出和通知配置 |

## 核心对象

| 对象 | 说明 |
| --- | --- |
| Ticket | 工单，代表一条客户请求或内部运营任务 |
| Assignment | 分派记录，记录当前负责人和历史分派变化 |
| Note | 客服备注，可见性分为内部、跨团队、审计 |
| SLA Policy | SLA 策略，定义响应和解决时限 |
| Audit Event | 审计事件，记录敏感操作 |
| Notification | 通知任务，负责提醒负责人和主管 |

## 关键流程

### 登录与权限

用户通过企业 SSO 登录。后端根据组织、团队和角色生成访问范围。前端只展示用户有权访问的工单、操作和导出入口。

### 工单处理

工单进入队列后，客服可以认领或由主管批量分派。处理过程中可以追加备注、切换状态、转交团队或关闭工单。每个敏感操作都写入审计日志。

### 批量分派

主管在列表中筛选一组工单后，可以按团队、负责人、优先级和 SLA 风险进行批量分派。系统需要防止重复提交、权限越界和部分失败不可见。

### 备注审计

备注内容进入保存流程前需要进行基础校验。涉及退款、隐私或投诉升级的备注会标记为审计重点，并可在审计页检索。

## 验收标准

- 运营主管可以在 200 条以内的筛选结果中完成批量分派；
- 批量操作出现部分失败时，界面能明确展示成功数量、失败数量和可重试项；
- 客服备注保存后能在详情页、审计日志和导出记录中保持一致；
- 未授权用户不能读取或操作其他团队工单；
- 所有用户可见文案通过 i18n key 渲染；
- 核心接口有契约测试或集成测试覆盖；
- 涉及 SSO、真实账号、外部通知验证，或会影响验收口径的通知策略决策进入 `HUMAN.md`。

## 文档边界

- 当前执行状态写入 `TODO.md`；
- 测试反馈和审查意见写入语义命名的 `fix_<desc>.md`，例如 `fix_audit-batch.md`；
- 人工执行事项和方向性人工决策写入 `HUMAN.md`；
- API 和前后端接口规则写入 `INTERFACE.md`；
- 测试策略写入 `TEST.md`；
- 架构说明写入 `ARCHITECTURE.md`；
- 稳定术语写入 `NICKNAME.md`。
