# 工作流 4：人工干预分流

> 场景：任务必须由人类完成，或代理发现某个困惑、选择、风险会显著影响项目方向、范围、架构或验收口径。

## 触发判断

以下事项进入 `HUMAN.md`：

- 代理无法独立完成的人工执行事项，例如真实账号登录、外部权限、实体设备、生产或预发环境人工验收。
- 代理发现的人工决策事项，例如会改变项目定位、功能边界、架构取舍、外部接口承诺或验收标准的问题。
- 代理认为继续猜测会造成明显方向漂移的 `AI 困惑` 或 `方向风险`。

能通过代码、文档、测试或模拟环境完成，且不影响方向性决策的事项，应继续留在 `TODO.md` 由代理处理。

## 分流步骤

1. 判断该事项是否阻塞具体执行。
2. 若阻塞具体执行，先在 `TODO.md` 建立或确认对应条目，并保持该 TODO 未完成。
3. 在 `HUMAN.md` 新增 `H-YYYYMMDD-01` 格式条目，标明类型：`人工执行` / `人工决策` / `AI 困惑` / `方向风险`。
4. 写清影响范围、代理暂停处理的部分，以及代理仍可继续推进的部分。
5. 若存在对应 TODO，TODO 写明：`阻塞：已转 HUMAN.md#H-...，待人工执行/决策`。
6. 若来源是 fix 或 fix-plan，在对应的 `fix_<desc>.md` / `fix-plan_<desc>.md` 条目标注"人工验证/决策已转 HUMAN.md#H-..."。
7. 代理避开受影响范围，继续推进不依赖该人工输入的其他 TODO。

## HUMAN 条目字段

- 来源
- 对应 TODO（如适用）
- 类型
- 状态
- 影响范围
- 代理暂停处理的部分
- 代理可继续推进的部分
- 为什么需要人工
- 前置条件（人工执行项适用）
- 操作步骤或需要回答的问题
- 期望结果或决策生效方式
- 反馈回填格式

## 人类反馈后

- 通过/已执行：对应 TODO 标 `[x]`。
- 已决策：代理按反馈恢复受影响范围的 TODO、plan、fix 或 fix-plan 处理。
- 不通过：根据反馈创建或更新 `fix_<desc>.md`（若属于缺陷反馈）或 `fix-plan_<desc>.md`（若属于范围扩展），再映射回 TODO。
- 不再需要/已取消：TODO 标 `[~]` 并说明废除原因；未绑定 TODO 的条目在 `HUMAN.md` 标记为已取消。
- 完成详情可移入 `.cairn/archive/human-YYYYMMDD.md`。
