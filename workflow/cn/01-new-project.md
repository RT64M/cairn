# 工作流 1：启动新项目

> 场景：空目录或刚初始化的仓库，要接入 `Cairn` 协议。

## 目标

让代理先建立文件约束，再进入计划讨论，最后才开始写代码。新项目不需要复制一整套模板文件，只需要复制根目录 `AGENTS.md` 模板，创建 `.cairn/`，并按规则**严格按顺序**创建项目自己的元文件。

## 创建顺序（不得跳步或并行）

### 步骤 1：创建项目目录并初始化 Git

### 步骤 2：复制 `AGENTS.md`（必须是项目第一个产生的文件）

```bash
cp template/AGENTS.zh.md my-project/AGENTS.md
```

英文项目可复制 `template/AGENTS.en.md`。

> 在 `AGENTS.md` 落地之前，**不得**创建任何其他元文件。

### 步骤 3：创建 `.cairn/`

在 `AGENTS.md` 之后立即创建 `.cairn/`。除根目录 `AGENTS.md` 外，所有 Cairn 管理文件都放在这里。

### 步骤 4：与用户讨论并定稿 `.cairn/plan.md`

总体原则：**讨论阶段充分发散，写入阶段严格收敛**。

#### 3.1 讨论阶段（充分发散）

- 主动与用户进行深入讨论，至少覆盖：项目定位、功能清单、数据模型、对外接口、验收标准。
- 主动识别计划中的潜在漏洞、未覆盖的边界场景、模糊的验收口径。
- 代理可在讨论中延伸提出衍生功能、潜在风险、可选方案，供用户参考。
- 每一处不确定之处必须**主动提问并等待用户确认**，不得以猜测或默认值随意填入。

#### 3.2 写入阶段（严格收敛）

将内容写入 `plan.md` 时必须分两层处理：

- **优先层 — 用户明确需求**：用户已明确表达的需求必须全部落实，不得遗漏或自行裁剪。
- **延伸层 — 代理建议**：代理在讨论中提出的衍生想法、扩展功能、边界处理建议，**必须逐项获得用户明确许可后方可写入** `plan.md`；未获许可的建议仅保留于讨论记录，不进入 plan。

#### 3.3 最终确认

plan 草稿完成后，必须由用户给出**最终确认**（"plan 定稿"或同等明确表态），代理方可将 `.cairn/plan.md` 写入，并进入后续步骤。

### 步骤 5：依次创建其余核心元文件

`.cairn/plan.md` 定稿并经用户最终确认后，按以下顺序创建：

1. `.cairn/ARCHITECTURE.md`
2. `.cairn/TODO.md`

`fix_<desc>.md` 与 `fix-plan_<desc>.md` 始终按需在 `.cairn/` 下创建，不预建空文件。

### 步骤 6：检查按需补充文件触发条件

在触发条件满足后才创建，不在启动阶段批量预建：

- 有对外接口：创建 `.cairn/INTERFACE.md`
- 项目复杂且用户要求测试：创建 `.cairn/TEST.md`
- 专有术语 ≥ 5 个：创建 `.cairn/NICKNAME.md`
- 有人工执行事项，或需要人类决策的方向性问题：创建 `.cairn/HUMAN.md`

### 步骤 7：把初始计划拆成 `.cairn/TODO.md` 步骤

确保后续每次代码改动都有对应条目。

只允许从已定稿的 `plan.md` 拆 TODO。用户发出的启动命令（例如“读取 AGENTS 并制作 plan”）只触发启动流程，不作为 TODO 条目的来源。

## 反模式

- 在 `AGENTS.md` 落地之前就开始建其他元文件。
- 把 Cairn 状态文件继续平铺在根目录，而不是放入 `.cairn/`。
- 跳过讨论阶段，直接落笔 `plan.md` 草稿。
- 未经用户明确许可，将代理提出的延伸建议写入 `plan.md`。
- 未获用户最终确认即开始创建 `.cairn/ARCHITECTURE.md` 或写代码。
- 没有 `plan.md` 就直接写代码。
- 把“根据 AGENTS 制作 plan”这类启动命令本身写成 TODO 来源。
- 把用户教程写进 `AGENTS.md`。
- 把接口细节写进 `plan.md`。
- 提前创建空的 `fix_<desc>.md` 或 `fix-plan_<desc>.md` 占位。
- 用 `fix_01.md` 这类纯序号命名新反馈批次。
