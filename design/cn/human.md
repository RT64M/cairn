# HUMAN.md 设计

`HUMAN.md` 是人类异步干预台账，记录代理不能独立完成的人工执行事项，以及代理认为会影响项目方向、范围、架构或验收标准的人工决策事项。

## 为什么需要

真实账号登录、外部权限、实体设备、真实浏览器人工验收等事项无法靠代理独立完成；同时，某些问题虽然代理可以猜测，但会影响项目定位、功能边界、架构取舍或验收口径，不应被代理静默决定。如果这些事项留在 `fix_<desc>.md` 或 `fix-plan_<desc>.md`，对应闭环会永久阻塞；如果只留在聊天里，下一次会话会遗忘。

`HUMAN.md` 让代理把需要人类执行、确认或决策的事项打包提交给人类。人类可随时修改状态、反馈或完成结果介入；代理则暂停触碰受影响范围，同时继续推进其他不依赖该决策的可执行 TODO，保证项目工作连贯。`fix-plan` 完成 plan 写入、来源标注和归档后，后续人工验证或方向决策应通过 TODO 或来源记录转入 `HUMAN.md`，不继续阻塞 fix-plan。

## 应写内容

- 人工事项 ID，例如 `H-YYYYMMDD-01`。
- 类型：`人工执行` / `人工决策` / `AI 困惑` / `方向风险`。
- 来源和对应 TODO（若该事项阻塞具体执行）。
- 当前状态。
- 影响范围。
- 代理暂停处理的部分。
- 代理可继续推进的部分。
- 为什么需要人类。
- 人类需要执行的步骤、回答的问题或可选决策。
- 期望结果或决策生效方式。
- 反馈回填格式。

## 不写内容

- 可由代理完成的修复。
- 普通开发 TODO。
- 测试方法索引。
- 用户教程。
- 不影响方向、范围、架构或验收口径的小实现细节。

## 与 TODO 的关系

阻塞具体工作的 `HUMAN.md` 条目必须对应一个 `TODO.md` 条目。TODO 保持未完成，并写明 `阻塞：已转 HUMAN.md#H-...，待人工执行/决策`。

仅用于记录方向性决策或代理困惑、尚未阻塞具体执行项的 `HUMAN.md` 条目，可以先引用来源文件或会话上下文；一旦该决策开始阻塞可执行工作，代理必须创建或确认对应 TODO，并把 TODO 指向该 `HUMAN.md` 条目。

## 推荐条目格式

```md
## H-YYYYMMDD-01：标题

- 类型：人工执行 / 人工决策 / AI 困惑 / 方向风险
- 来源：TODO N.M / plan.md / fix-plan_x.md / 当前会话
- 对应 TODO：TODO N.M（如适用）
- 状态：待人类执行 / 待人类决策 / 已反馈 / 已完成 / 已取消
- 影响范围：
- 代理暂停处理的部分：
- 代理可继续推进的部分：
- 为什么需要人类：
- 人类需要执行或回答：
- 期望结果或决策生效方式：
- 反馈回填格式：
```
