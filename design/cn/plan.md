# plan.md 设计

`plan.md` 是项目稳定大纲，回答“这个项目要做什么、为什么、做到什么程度算完成”。

## 为什么需要

TODO 会频繁变化，用户文档面向用户，聊天记录会丢失。`plan.md` 保存低频稳定设计，让代理在多次会话后仍能理解项目方向。

## 应写内容

- 项目定位。
- 用户和核心场景。
- 功能清单。
- 数据模型和核心对象。
- 需要哪些接口或入口。
- 验收标准。
- 明确非目标。

## 不写内容

- 当前执行步骤，属于 `TODO.md`。
- 接口参数和响应细节，属于 `INTERFACE.md`。
- Cairn 文件结构、信息归属、信息流、代码目录和依赖方向，属于 `ARCHITECTURE.md`。
- 测试反馈和 review 条目，属于 `fix_<desc>.md`。

## 修改路径

`plan.md` 不能在普通会话中随手改，只有两类入口：

- `fix_<desc>.md`：修正现状与 plan 描述之间的偏差，在 fix 归档时按需回写。
- `fix-plan_<desc>.md`：新增、扩展或修订 plan 内容。用户最终确认后立即写入 `plan.md`，在对应条目标注来源和修改日期，优先归档 fix-plan，再从新版 plan 派生或调整 TODO。

来源标注是**每条一个、只替换不追加的单一标记**。修订一个已带标记的条目时，重写该标记而不是再追加一条引用，最多保留两条引用（初次来源与最近一次修订）。完整修订链已存于 `archive/` 与 git 历史，因此 plan 条目不得堆叠越来越长的"来源 / 修订来源"列表。
