# TODO.md 设计

`TODO.md` 是执行台账，记录当前正在做什么、完成到哪、哪些事项阻塞、来源是什么。

## 为什么需要

代理执行会跨会话、跨人、跨工具。`TODO.md` 让“当前状态”不依赖聊天上下文，也让每次改动都有来源和验收点。

## 状态符号

- `[x]` 已完成。
- `[ ]` 待完成。
- `[!]` 已修改：原条目仍部分有效，但被新计划覆盖。
- `[~]` 已废除：原条目取消或替换，保留用于回溯。
- `阻塞：` 记录具体原因和下一步恢复动作。

## 应写内容

- 步骤编号、标题和来源。
- 可执行子项。
- 验证命令或验收结果。
- 来自 `fix_<desc>.md` 的反馈映射。
- 从已确认、已写入 `plan.md` 且已优先归档的 `fix-plan_<desc>.md` 派生出的执行步骤。
- 受 plan 修订影响的旧条目处理结果，例如 `[!]`、`[~]`、重开 TODO 或归档补充说明。
- 指向 `HUMAN.md` 的人工阻塞。
- 接口变更是否已同步 `INTERFACE.md`。

## 不写内容

- 稳定设计动机，属于 `plan.md`。
- 项目结构、文件职责、信息流和代码目录分工，属于 `ARCHITECTURE.md`。
- 测试方法索引，属于 `TEST.md`。
- 用户原始命令、当前会话说明或“根据 AGENTS 制作 plan”这类启动动作；它们只能触发 plan / fix 流程，不是 TODO 来源。
- 完成后的完整历史，归档到 `.cairn/archive/`。

## 来源边界

TODO 的来源只能是两类：`plan.md` 当前版本派生出的执行步骤，或 `fix_<desc>.md` 映射出的缺陷 / 审查 / 测试反馈。`fix-plan_<desc>.md` 先写入并归档到 `plan.md`，再由新版 `plan.md` 派生 TODO；因此 TODO 不直接以 fix-plan、用户命令或当前会话为来源。

## 归档

归档是 TODO 步骤完成闭环的一部分，不是可选清理动作。每次更新 `TODO.md` 后都必须检查归档条件：当一个步骤所有子项都收敛为 `[x]` 或 `[~]`，且无 `[ ]`、`[!]`、阻塞项时，必须在同次会话内移入 `.cairn/archive/done-YYYYMMDD.md`，原位只留面包屑。

仍被活跃步骤反向引用的步骤暂不归档；引用关系闭合后必须立即归档。若后续 `fix-plan_<desc>.md` 修订影响已归档 TODO，应先查对应归档，再决定补充说明或重开新 TODO。
